# gameradar_worker

Фоновый процесс GameRadar и единственная часть системы, которая обращается к Steam. Запрашивает цены, онлайн, описания, отзывы и список игр, пишет их в PostgreSQL и решает, кому отправить уведомление о цене.

## Как устроен

```
Scheduler ──(раз в минуту: что пора обновить?)──▶ PostgreSQL
    │
    ▼  задачи с приоритетом
Очередь в Redis ──▶ полоса store ──▶ SteamClient ──▶ store.steampowered.com
                ├─▶ полоса api   ──▶ SteamClient ──▶ api.steampowered.com
                └─▶ полоса local ──▶ отложенные уведомления
                         │
                         ▼
              PostgreSQL + NotificationService
```

- **SteamClient** — единая точка выхода в Steam. Перед каждым запросом резервирует слот в ограничителе своего хоста: не чаще 1 запроса в 1,5 с. Ограничитель хранится в Redis, поэтому лимит общий для всех копий worker.
- **429/403**: хост встаёт на паузу 1 → 2 → 4 → 8 минут (дальше по 8), задача возвращается в очередь. Успешный ответ сбрасывает счётчик.
- **Временные ошибки** (сеть, 5xx, неожиданный ответ): повтор через 30 с, 1, 2, 4, 8 минут, после 6 попыток задача отбрасывается. Постоянные ошибки (400, 401) отбрасываются сразу.
- **Очередь**: задача с тем же id не попадает в очередь повторно. Взятая в работу задача арендуется на 10 минут: если worker упал, она вернётся сама.
- **Приоритет**: крайний срок обновления минус бонус за подписчиков, по 10 минут за каждое удвоение их числа. Задачи выполняются по ближайшему сроку. Если лимита не хватает, все интервалы растягиваются равномерно, а игры с подписчиками идут раньше.

## Частоты

| Данные | Интервал | Хост |
|---|---|---|
| Цены (пакетами по 50) | 2–6 ч, при `SALE_MODE=true` 45–60 мин | store |
| Онлайн топа | 25–30 мин | api |
| Онлайн отслеживаемых вне топа | 1–3 ч | api |
| Отзывы | 20–24 ч | store |
| Описание (en + ru, 2 запроса) | 6–7 дней | store |
| Топ-100 Steam (чарт) | 30 мин | api |
| Список игр | 24 ч | api |
| Обложки (header 460×215) | один раз и при смене адреса | CDN Steam (`*.steamstatic.com`) |
| Сжатие онлайна старше 30 дней | 24 ч | — |

Онлайн топа обновляется раз в 30 минут, а не в 15. Лимит 1 запрос в 1,5 с даёт 2400 запросов в час на хост, а онлайн запрашивается отдельно для каждой игры. Опрос 1000 игр раз в 15 минут — это 4000 запросов в час.

## Как строится топ-1000

1. Раз в 30 минут Steam отдаёт топ-100 одним запросом (`GetGamesByConcurrentPlayers`). Это сразу 100 замеров онлайна.
2. Кандидаты в топ — игры, уже стоящие в топе, и игры, чей пик за 24 ч не ниже онлайна игры на 1000-м месте. Их онлайн обновляется раз в 30 минут.
3. **Разведка**: когда полоса api простаивает, worker замеряет онлайн игр, которые ещё не замерял (или не замерял 30 дней). Так находятся новые кандидаты.
4. Каждые 5 минут места пересчитываются по свежим (до 3 ч) замерам.

Сразу после первого запуска топ состоит из топ-100 Steam и растёт по мере разведки.

## Обложки

Приложение не обращается к Steam даже за картинками (правило 1). Обложки отслеживаемых, недавно открытых и топовых игр скачивает worker: полоса `cdn`, тот же лимит 1 запрос в 1,5 с на хост и те же паузы на 429/403. Хранятся они в таблице `game_images`, сервер отдаёт их по своему адресу.

- **Что скачивается:** только HTTPS с доменов CDN Steam, только `image/jpeg|png|webp`, не больше 1 МБ.
- **Мёртвый адрес** (404 или не картинка) обнуляется, новый придёт с обновлением описания.
- **Заново** обложка скачивается, только если Steam сменил её адрес (параметр `?t=`).

## Уведомления

Решение принимает чистая функция `decideNotification`:

- уведомить, если цена не выше `target_price` или скидка не меньше `min_discount_pct`;
- повторно уведомлять, только если цена опустилась **ниже** `last_notified_price`;
- если условие перестало выполняться, отметка сбрасывается, и следующее снижение снова даст уведомление;
- в тихие часы (по часовому поясу пользователя) проверка откладывается до их конца.

Отправка — FCM HTTP v1 (`FcmNotifier`): авторизация сервисным аккаунтом Firebase через googleapis_auth, уведомление на все устройства пользователя, тексты на его языке. Например: «Cyberpunk 2077 — скидка 50%» / «8 999 ₸ вместо 17 999 ₸». Токены, которые FCM называет недействительными (`UNREGISTERED` и т.п.), удаляются. Пока не заданы `FCM_PROJECT_ID` и `FCM_SERVICE_ACCOUNT_FILE`, работает `LoggingNotifier`: он только пишет в журнал и не ставит отметку, поэтому уведомления не теряются.

Проверка настройки без ожидания скидки: `dart run tool/send_test_push.dart` отправляет тестовое уведомление на последнее зарегистрированное устройство.

## Запуск и тесты

```bash
dart test                 # unit-тесты (ограничитель, пауза, очередь, Steam-клиент, уведомления)
dart test -t db           # SQL на настоящем PostgreSQL (пересоздаёт схему!)
dart test -t redis        # Lua-скрипты очереди и ограничителя на настоящем Redis
```

Для интеграционных тестов нужны переменные `TEST_DATABASE_URL=postgres://...?sslmode=disable` и `TEST_REDIS_URL=redis://localhost:6379/15`. Разбор ответов Steam тестируется в пакете `shared` (`test/steam`) на образцах реальных ответов.

Переменные окружения описаны в корневом `.env.example`: `DATABASE_URL`, `REDIS_URL`, `STEAM_API_KEY`, `DEFAULT_REGION`, `SALE_MODE`.
